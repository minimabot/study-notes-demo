@topic vpc/internet-access/igw

**인터넷 게이트웨이(Internet Gateway)** 는 VPC와 인터넷 사이의 출입구다. AWS가 수평으로 늘리고 중복으로 운영하는 구성 요소라서, 게이트웨이 자체가 대역폭 병목이나 가용성 위험이 되지 않는다. IPv4와 IPv6를 모두 다룬다. VPC 하나에는 인터넷 게이트웨이를 {{fact:vpc.quota.igw-per-vpc}}만 붙일 수 있다. 게이트웨이 자체 요금은 없고, 이를 거쳐 나가는 데이터 전송 요금은 따로 붙는다.

인터넷 게이트웨이를 만들어 VPC에 붙이는 것만으로는 아무 일도 일어나지 않는다. 인스턴스가 인터넷과 통신하려면 다음이 모두 맞아야 한다.

| 조건 | 내용 |
|---|---|
| 게이트웨이 연결 | 인터넷 게이트웨이를 VPC에 연결한다 |
| 라우팅 | 서브넷의 라우팅 테이블에 `0.0.0.0/0`(IPv6는 `::/0`) → 인터넷 게이트웨이 경로가 있다 |
| 주소 | 인스턴스에 퍼블릭 IPv4 주소나 탄력적 IP 주소, 또는 IPv6 주소가 있다 |
| 필터 | 보안 그룹과 네트워크 ACL이 그 트래픽을 허용한다 |

**퍼블릭 서브넷(public subnet)** 과 **프라이빗 서브넷(private subnet)** 을 가르는 기준은 두 번째 줄 하나다. 연결된 라우팅 테이블에 인터넷 게이트웨이로 가는 경로가 있으면 퍼블릭, 없으면 프라이빗이다. 그래서 프라이빗 서브넷의 인스턴스는 퍼블릭 IP 주소를 갖고 있어도 인터넷과 통신하지 못한다. 경로는 꼭 `0.0.0.0/0`일 필요는 없다. 회사 사무실의 공인 주소 대역처럼 좁게 잡을 수도 있다. 라우팅 테이블 자체는 {{ch:vpc/subnets-routing}}에서 다룬다.

**주소 변환.** 인스턴스 운영 체제는 VPC 안의 프라이빗 IPv4 주소만 안다. 인터넷 게이트웨이가 인스턴스 대신 일대일 NAT를 한다. 나가는 패킷의 출발지를 인스턴스의 퍼블릭 IPv4(또는 탄력적 IP) 주소로 바꾸고, 들어오는 패킷의 목적지를 프라이빗 주소로 되돌린다. Amazon이 제공한 IPv6 주소는 전 세계에서 고유하고 인터넷에 광고되므로 변환 없이 그대로 퍼블릭이다. IPAM으로 받은 사설 IPv6(ULA·사설 GUA)는 인터넷에 광고되지 않고, 인터넷 게이트웨이를 거쳐도 직접 나가지 못한다.

**기본 VPC와 직접 만든 VPC.** 기본 VPC에는 인터넷 게이트웨이, IPv4 `0.0.0.0/0` 경로, 기본 서브넷의 퍼블릭 IPv4 자동 할당이 처음부터 들어 있다. 직접 만든 VPC에는 셋 다 없다. 직접 만든 서브넷은 퍼블릭 IPv4 자동 할당 속성이 꺼져 있다(EC2 인스턴스 시작 마법사가 만든 서브넷은 예외로 켜져 있다). IPv6 `::/0` 경로와 IPv6 자동 할당은 어느 쪽에도 기본으로 없다.

@topic vpc/internet-access/egress-only

Amazon 제공 IPv6 주소는 그대로 퍼블릭이다. 인스턴스가 인터넷으로 나가는 것은 허용하되 인터넷이 먼저 연결을 걸어오지는 못하게 하려면 **송신 전용 인터넷 게이트웨이(Egress-only Internet Gateway)** 를 쓴다. 라우팅 테이블에 `::/0`(또는 특정 IPv6 대역) → 송신 전용 인터넷 게이트웨이 경로를 넣으면 된다.

- **IPv6 전용이다.** IPv4로 같은 일을 하려면 NAT 게이트웨이를 쓴다({{ch:vpc/nat}}).
- **상태 저장(stateful)이다.** 안에서 나간 요청의 응답은 돌려보낸다.
- **보안 그룹을 붙일 수 없다.** 그 서브넷의 트래픽을 걸러야 한다면 네트워크 ACL을 쓴다.
- **요금.** 게이트웨이 요금은 없고 데이터 전송 요금만 붙는다.

| 출구 | 대상 트래픽 | 밖에서 먼저 연결 |
|---|---|---|
| 인터넷 게이트웨이 | IPv4·IPv6 | 가능 |
| 송신 전용 인터넷 게이트웨이 | IPv6 | 불가 |
| NAT 게이트웨이 | IPv4 (NAT64로 IPv6→IPv4) | 불가 |

@topic vpc/internet-access/eip

**탄력적 IP 주소(Elastic IP address)** 는 계정에 할당해 두고 쓰는 고정 퍼블릭 IPv4 주소다. 자동 할당된 퍼블릭 IPv4는 인스턴스를 바꾸면 달라지지만, 탄력적 IP는 직접 놓아줄(release) 때까지 계정에 남는다.

- **네트워크 인터페이스의 속성이다.** 한 번에 인스턴스나 네트워크 인터페이스 하나에만 붙는다. 다른 인스턴스로 옮겨 붙일 수 있어서, 인스턴스가 고장 나면 주소를 대체 인스턴스로 옮겨 장애를 가린다. DNS 레코드나 상대방 방화벽 규칙에 주소를 고정해 둘 때도 쓴다.
- **기본 퍼블릭 IPv4는 사라진다.** 기본 네트워크 인터페이스에 탄력적 IP를 붙이면 원래 있던 퍼블릭 IPv4 주소는 풀로 돌아간다. 탄력적 IP를 떼면 기본 인터페이스에 새 퍼블릭 IPv4가 잠시 뒤 다시 할당된다. 다만 인스턴스에 두 번째 네트워크 인터페이스가 붙어 있으면 다시 할당되지 않는다.
- **리전 단위이고 IPv4 전용이다.** IPv6 탄력적 IP는 없다.
- **할당량.** 기본은 리전당 {{fact:vpc.quota.eip-per-region}}다. 사설 리소스가 많다면 각자 주소를 주지 말고 NAT 장치 뒤에 두어 주소를 아낀다.

**퍼블릭 IPv4 요금.** 문서의 요금 안내는 탄력적 IP를 "퍼블릭 IPv4 주소" 요금 항목에 넣는다. 인스턴스에 자동 할당된 퍼블릭 IPv4와 탄력적 IP 모두 사용 시간에 따라 비용이 집계된다. Cost Explorer에서 사용 중인 주소는 `PublicIPv4InUseAddress`, 어디에도 붙지 않았거나 중지된 인스턴스에 붙은 주소는 유휴 주소 `PublicIPv4IdleAddress`로 나뉜다. 쓰지 않는 탄력적 IP를 들고 있어도 비용이 생긴다는 뜻이다. 단가는 요금 페이지에서 확인한다.

@topic vpc/internet-access/bpa

**VPC 퍼블릭 액세스 차단(VPC Block Public Access, BPA)** 은 계정·리전 단위로 인터넷 게이트웨이와 송신 전용 인터넷 게이트웨이를 오가는 트래픽을 한 번에 막는 설정이다. 개별 라우팅 테이블이나 보안 그룹 설정보다 우선한다.

| 모드 | 동작 |
|---|---|
| 양방향(Bidirectional) | 이 리전의 인터넷 게이트웨이·송신 전용 인터넷 게이트웨이를 오가는 트래픽을 모두 막는다 |
| 수신 전용(Ingress-only) | 인터넷에서 들어오는 트래픽을 막는다. NAT 게이트웨이와 송신 전용 인터넷 게이트웨이를 통한 바깥 방향 연결은 허용한다 |

특정 VPC나 서브넷은 **제외(exclusion)** 로 풀어 줄 수 있다. 제외에는 양방향 허용과 송신 전용 허용이 있다. 인터넷에 노출되는 Application Load Balancer·Network Load Balancer, NAT 게이트웨이도 인터넷 게이트웨이를 거치므로 차단 대상이다. Site-to-Site VPN, 전송 게이트웨이(Transit Gateway) 같은 사설 연결은 영향을 받지 않는다. 시험 가이드에 이 기능을 직접 가리키는 문장은 없다.
