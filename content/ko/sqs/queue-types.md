@topic sqs/queue-types/compare

SQS 큐는 두 종류다. **표준 대기열(Standard queue)** 과 **FIFO 대기열(FIFO queue)** 이다. 큐를 만들 때 하나를 골라야 하고, 둘은 세 가지 점에서 다르다. 순서, 중복, 처리량이다.

| 항목 | 표준 대기열 | FIFO 대기열 |
|---|---|---|
| 순서 | 최대한 지키려 하지만 보장하지 않는다 (최선의 순서 지정) | 같은 메시지 그룹 안에서 보낸 순서대로 받는다 |
| 중복 | 최소 1회 전송. 드물게 같은 메시지가 두 번 온다 | 정확히 1회 처리. 중복 제거 간격({{fact:sqs.fifo.dedup.interval}}) 안에 같은 중복 제거 ID로 다시 보낸 메시지는 전송 성공으로 응답하되 소비자에게 전달하지 않는다 |
| 처리량 | API 작업별로 초당 호출 수가 사실상 무제한이다 | 기본 모드에서 파티션당 API 작업별 {{fact:sqs.fifo.tps.per-partition}}, 배치를 쓰면 {{fact:sqs.fifo.batched.msgs-per-sec}} |
| 이름 | 제한 없음 (길이 한도만 있다) | 반드시 `.fifo`로 끝나야 한다 |

FIFO는 **높은 처리량 모드(high throughput mode)** 를 켜면 한도가 훨씬 올라간다. 이 값은 리전마다 다르다. 예를 들어 서울 리전은 배치 없이 {{fact:sqs.fifo.ht.tps.other}}이다.

두 종류 모두 메시지를 여러 서버에 중복 저장하고, 가시성 제한 시간(Visibility Timeout)으로 받은 메시지를 숨긴다. 이 공통 동작은 종류와 상관없이 같다.

@topic sqs/queue-types/choose

고르는 기준은 하나의 질문으로 시작한다. **"순서가 바뀌거나 같은 메시지가 두 번 오면 결과가 틀어지는가?"**

- **아니라면 표준 대기열**을 쓴다. 처리량 걱정이 거의 없다. 대신 소비자는 같은 메시지를 두 번 처리해도 결과가 같도록(멱등하게) 만든다.
- **그렇다면 FIFO 대기열**을 쓴다. 단, 순서가 필요한 범위가 어디까지인지 먼저 따진다. 대개 "전체 순서"가 아니라 "사용자별·주문별 순서"면 충분하다. 이때 사용자 ID나 주문 ID를 메시지 그룹 ID로 쓰면, 그룹 안의 순서는 지키면서 그룹끼리는 나란히 처리할 수 있다.

| 이런 일이라면 | 맞는 큐 |
|---|---|
| 업로드한 영상을 뒤에서 변환한다 | 표준 |
| 대량의 검증 요청을 작업자 여럿에게 나눠 준다 | 표준 |
| 나중에 DB에 한꺼번에 넣을 기록을 모은다 | 표준 |
| 사용자가 입력한 명령을 입력한 순서대로 실행한다 | FIFO |
| 상품 가격 변경을 바뀐 순서대로 반영한다 | FIFO |
| 회원 가입이 끝난 뒤에 수강 신청을 처리한다 | FIFO |

순서가 필요해 보여도 표준으로 풀리는 경우가 있다. 예를 들어 "가장 최근 값만 반영하면 되는" 데이터는 메시지에 시각이나 버전 번호를 넣고, 소비자가 더 오래된 값은 버리게 하면 된다.

각 종류의 자세한 동작은 {{ch:sqs/standard}}와 {{ch:sqs/fifo}}에서 다룬다.

@topic sqs/queue-types/fixed

큐 종류는 **만든 뒤에 바꿀 수 없다.** 표준 대기열을 FIFO로 바꾸려면 FIFO 큐를 새로 만들어야 한다. 옮길 때는 큐만 바꾸는 것으로 끝나지 않고 애플리케이션도 함께 고쳐야 한다.

- **메시지 그룹 ID:** FIFO 큐에 보내는 모든 메시지에 넣어야 한다. 빠뜨리면 전송이 실패한다.
- **중복 제거:** 메시지마다 중복 제거 ID를 주거나, 본문이 늘 다르다면 콘텐츠 기반 중복 제거를 켠다.
- **지연:** FIFO는 메시지 하나하나에 지연을 줄 수 없고 큐 단위 지연만 쓸 수 있다. 메시지마다 `DelaySeconds`를 넣던 코드는 고쳐야 한다.
- **이름:** 새 큐 이름은 `.fifo`로 끝나야 한다. 이 접미사도 큐 이름 길이 한도({{fact:sqs.queue-name.max-length}})에 포함된다.

> **주의:** 처음부터 FIFO가 필요한지 따져 보고 고른다. 나중에 바꾸면 큐를 새로 만들고, 생산자와 소비자가 새 큐를 보도록 옮기는 작업이 따른다.
