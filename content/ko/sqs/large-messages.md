@topic sqs/large-messages/size-limit

SQS 메시지 하나의 크기는 최대 {{fact:sqs.message.max-size}}다. 이 크기에는 본문뿐 아니라 메시지 속성도 들어간다. 이 값은 예전에 더 작았고 2025년에 올라갔다. 오래된 자료나 라이브러리 문서에는 옛 값이 남아 있으니 공식 할당량 페이지에서 다시 확인한다.

큐 속성 `MaximumMessageSize`(콘솔의 최대 메시지 크기)로 이보다 작게 제한할 수도 있다. 가장 작게는 {{fact:sqs.queue.max-message-size.min}}까지다. 기본값은 SQS가 허용하는 최댓값과 같다. 정한 크기를 넘는 메시지는 SQS가 받아 주지 않는다.

크기는 요금과도 이어진다. SQS는 페이로드를 {{fact:sqs.billing.chunk-size}} 단위로 잘라서, 조각 하나를 요청 한 건으로 계산한다. 그래서 최대 크기의 메시지 하나를 보내면 요청 {{fact:sqs.billing.requests-per-max-message}}으로 계산된다. 큰 데이터를 큐에 그대로 실어 보내면 크기 한도에 앞서 요금이 먼저 늘어난다.

@topic sqs/large-messages/claim-check

한도보다 큰 데이터는 큐에 직접 싣지 않는다. 데이터 본문은 Amazon S3 버킷에 저장하고, 큐에는 그 객체를 가리키는 **참조(버킷 이름과 키)** 만 보낸다. 소비자는 메시지를 받아 참조를 읽고, S3에서 본문을 가져와 처리한다. 짐은 맡기고 보관증만 들고 다니는 것과 같아서 이 방식을 클레임 체크(Claim Check) 패턴이라고 부른다.

이렇게 하면 두 가지가 좋아진다.

- **크기 한도를 넘을 수 있다.** 큐에는 작은 참조만 지나가므로 메시지 한도의 영향을 받지 않는다.
- **큐는 가볍게 유지된다.** 큐에 오가는 데이터가 작아서 요청 요금이 적게 나온다. 같은 큰 데이터를 여러 소비자가 읽어야 할 때도 S3 객체 하나를 함께 쓰면 된다.

대신 지켜야 할 것이 생긴다. 생산자는 S3에 저장하는 일과 큐에 보내는 일을 둘 다 해야 하고, 소비자는 S3 읽기 권한이 있어야 한다. 처리가 끝난 S3 객체를 누가 언제 지울지도 정해야 한다.

@topic sqs/large-messages/extended-client

이 패턴을 직접 짜지 않아도 되도록 AWS는 **Amazon SQS 확장 클라이언트 라이브러리(Extended Client Library)** 를 제공한다. Java용과 Python용이 있고, Standard 큐와 FIFO 큐에서 모두 쓸 수 있다. 이 라이브러리로 다룰 수 있는 페이로드는 최대 {{fact:sqs.extended.max-payload}}다.

라이브러리는 평소 쓰는 SQS 클라이언트를 감싼다. 보낼 때와 받을 때 하는 일은 다음과 같다.

| 동작 | 라이브러리가 하는 일 |
|---|---|
| 보내기 | 본문이 기준 크기보다 크면 S3에 올리고, 큐에는 참조만 보낸다. 항상 S3를 거치게 설정할 수도 있다 |
| 받기 | 참조를 읽어 S3에서 본문을 가져와 돌려준다 |
| 삭제 | 메시지를 지울 때 S3 객체도 함께 지울 수 있다 |

S3로 옮기는 기본 기준 크기는 {{fact:sqs.extended.threshold.default}}다. 이 값은 메시지 한도가 올라가기 전의 한도와 같다. 그래서 지금의 메시지 한도보다 작은 메시지도 기본 설정에서는 S3로 옮겨진다. 필요하면 설정에서 기준을 바꾼다.

> **주의:** 이 라이브러리는 해당 언어의 AWS SDK(Java용 SDK, Python용 Boto3)와 함께 쓸 때만 동작한다. AWS CLI, SQS 콘솔, SQS HTTP API, 다른 언어의 SDK로는 S3에 맡긴 본문을 자동으로 꺼내 오지 못한다. 할당량 페이지는 동기식 클라이언트에서만 동작한다고도 적고 있다. 생산자와 소비자가 서로 다른 언어나 도구를 쓰면, 받는 쪽에는 참조만 보인다.

@topic sqs/large-messages/cleanup

S3에 맡긴 본문은 메시지가 사라져도 저절로 지워지지 않는다. 남는 객체는 저장 요금을 계속 낸다.

- **정상 처리:** 소비자가 확장 클라이언트로 메시지를 지울 때 S3 객체도 함께 지우게 한다. Java 라이브러리는 이 동작이 기본이고, Python 예제는 `delete_payload_from_s3`를 켜서 지운다.
- **지워지지 않는 경우:** 메시지가 보관 기간(최대 {{fact:sqs.retention.max}})을 넘겨 만료되거나, DLQ로 갔다가 그대로 버려지거나, 라이브러리를 쓰지 않는 도구로 지우면 S3 객체만 남는다.
- **안전망:** 버킷에 S3 수명 주기(Lifecycle) 규칙을 걸어 일정 기간이 지난 객체를 지운다. AWS의 Java 예제도 버킷을 만들 때 만료 규칙을 함께 건다. 이 기간은 원본 큐와 DLQ에서 메시지가 머물 수 있는 시간보다 길게 잡는다. 더 짧으면 아직 처리하지 않은 메시지의 본문이 먼저 사라진다.

DLQ와 보관 기간은 {{ch:sqs/dlq}}에서 다룬다.
