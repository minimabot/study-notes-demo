@topic ec2/instance-store-efs/instance-store

**인스턴스 스토어(instance store)** 는 인스턴스가 올라간 호스트 컴퓨터에 물리적으로 붙은 디스크를 블록 스토리지로 쓰는 것이다. 볼륨 수와 크기는 인스턴스 유형과 크기가 정한다. 인스턴스 스토어가 아예 없는 유형도 많다. 유형 이름에 `d`가 붙으면 인스턴스 스토어가 있다는 뜻이다({{ch:ec2/instance-types}}).

- 요금이 따로 없다. 인스턴스 요금에 들어 있다.
- 시작할 때만 붙일 수 있다. 실행 뒤에 붙이거나, 떼어서 다른 인스턴스로 옮길 수 없다.
- 볼륨은 그 인스턴스가 살아 있는 동안만 있다. 인스턴스보다 오래 남도록 설정하는 방법은 없다.

**데이터가 남는가.** 핵심은 "재부팅은 남고, 호스트를 떠나면 지워진다"이다.

| 일 | 인스턴스 스토어 데이터 |
|---|---|
| 재부팅(사용자, OS, AWS 예정 재부팅) | 남는다 |
| 중지, 최대 절전, 종료 | 지워진다. 모든 블록이 암호학적으로 지워진다 |
| 인스턴스 유형 변경 | 남지 않는다. 새 유형이 인스턴스 스토어를 주더라도 빈 볼륨이다 |
| OS에서 종료(shutdown) | 남지 않는다 |
| 인스턴스 폐기, 자동 복구 | 남지 않는다 |
| 기반 디스크 고장 | 고장 난 디스크의 데이터는 남지 않는다 |
| 정전 | 재부팅 뒤 남는다 |

EBS 기반 AMI를 인스턴스에서 만들어도 인스턴스 스토어 데이터는 AMI에 들어가지 않는다. 중지·종료와 데이터의 관계는 {{ch:ec2/instance-lifecycle}}에서 더 다룬다.

**알맞은 용도.** 자주 바뀌고 잃어도 되는 데이터다. 버퍼, 캐시, 스크래치 데이터, 임시 파일, 그리고 여러 인스턴스에 복제해 두는 데이터(로드 밸런서 뒤 웹 서버 무리에 같은 사본을 두는 경우 등). 오래 남겨야 하는 데이터는 직접 EBS, S3, EFS 같은 영구 스토리지로 복사해야 한다.

**NVMe SSD 인스턴스 스토어.** 일부 유형은 NVMe SSD로 인스턴스 스토어를 준다. 데이터는 하드웨어 모듈이 XTS-AES-256으로 암호화한다. 키는 장치마다 다르고, 인스턴스를 중지하거나 종료하면 키가 없어져 되살릴 수 없다. 이 암호화는 끌 수 없고 자기 키를 넣을 수도 없다.

@topic ec2/instance-store-efs/efs-basics

**Amazon EFS(Elastic File System)** 는 서버리스 공유 파일 스토리지다. 용량을 미리 정하지 않는다. 파일을 넣고 지우는 만큼 늘고 준다.

- **프로토콜.** NFS 버전 4.0, 4.1을 쓴다. 여러 NFS 클라이언트가 동시에 탑재해 같은 파일을 읽고 쓴다. POSIX 권한, 강한 일관성(close-to-open), 파일 잠금을 지원한다.
- **누가 쓰나.** EC2, ECS, EKS, Lambda, Fargate. Direct Connect나 Site-to-Site VPN으로 연결된 온프레미스 Linux 서버도 탑재할 수 있다.
- **Linux 전용.** Windows 기반 EC2 인스턴스에서는 지원하지 않는다. Windows 공유 파일이 필요하면 아래 FSx for Windows File Server를 본다.

**파일 시스템 유형.**

| 유형 | 데이터 위치와 특징 |
|---|---|
| 리전(Regional) | 한 리전 안 {{fact:ec2.efs.regional.az.min}} 가용 영역에 나눠 저장한다. 가용 영역 하나가 안 돼도 데이터에 닿는다 |
| 단일 영역(One Zone) | 가용 영역 하나에 저장한다. 그 영역을 잃으면 데이터를 잃을 수 있다. EFS가 AWS Backup으로 자동 백업한다. 일부 가용 영역에서만 만들 수 있다 |

**탑재 대상(mount target).** VPC 안에서 EFS에 닿는 NFS 엔드포인트다. 서브넷에 만들고 IP 주소를 받는다.

- 탑재 대상은 {{fact:ec2.efs.mt.per-az}}만 둔다. 한 영역에 서브넷이 여럿이어도 그중 하나에만 만든다. 같은 영역의 다른 서브넷 인스턴스도 그 탑재 대상을 쓴다.
- 파일 시스템 DNS 이름은 인스턴스와 같은 가용 영역의 탑재 대상 IP로 풀린다. 성능과 요금 때문에 같은 영역의 탑재 대상으로 탑재하라고 문서가 권한다. 다른 영역 탑재 대상으로 가면 EC2 데이터 전송 요금이 붙는다.
- 한 파일 시스템의 탑재 대상은 한 번에 VPC 하나에만 둔다.
- 탑재 대상에는 퍼블릭 IP를 붙일 수 없다. 같은 VPC, 연결된 VPC, VPN·Direct Connect로 이어진 온프레미스에서만 닿는다.

**보안 그룹.** 탑재 대상의 보안 그룹은 인스턴스의 보안 그룹에서 오는 NFS 포트(TCP 2049) 인바운드를 허용해야 한다. 인스턴스 쪽은 탑재 대상으로 가는 같은 포트의 아웃바운드가 열려 있어야 한다. 서로를 보안 그룹 ID로 참조하는 방식이 관리하기 쉽다({{ch:vpc/security-groups-nacl}}). 탑재 대상의 서브넷과 클라이언트 서브넷 사이에 네트워크 ACL이 있다면 응답 트래픽까지 열어야 한다.

@topic ec2/instance-store-efs/efs-classes-performance

**스토리지 클래스(storage class).**

| 클래스 | 맞는 데이터 |
|---|---|
| EFS Standard | 자주 쓰는 활성 데이터. SSD 기반이라 지연이 가장 낮다. 새 데이터는 늘 여기에 먼저 쓴다 |
| EFS Infrequent Access(IA) | 분기에 몇 번 읽는 데이터. 첫 바이트 지연이 수십 밀리초 |
| EFS Archive | 1년에 몇 번 이하로 읽는 데이터. 최소 저장 기간 {{fact:ec2.efs.archive.min-duration}}. 탄력적 처리량 모드에서만 쓴다 |

- IA와 Archive는 저장 요금이 싸지만 읽을 때와 클래스를 옮길 때 데이터 접근 요금이 붙는다. 파일당 최소 과금 크기는 {{fact:ec2.efs.min-billing}}이다.
- 파일 이름, 소유자, 디렉터리 구조 같은 메타데이터는 늘 Standard에 있다. 디렉터리 목록을 보는 것은 파일 접근으로 치지 않는다.

**수명 주기 관리(lifecycle management).** 파일이 Standard에서 마지막으로 접근된 때를 기준으로 클래스를 옮긴다. 정책은 파일 시스템 전체에 걸린다.

| 정책 | 기본값 |
|---|---|
| IA로 전환 | Standard에서 {{fact:ec2.efs.ia.default}} 동안 접근하지 않은 파일 |
| Archive로 전환 | Standard에서 {{fact:ec2.efs.archive.default}} 동안 접근하지 않은 파일 |
| Standard로 되돌리기 | 기본은 되돌리지 않는다. 지연에 민감하면 "첫 접근 시(On first access)"로 둔다 |

**성능 모드(performance mode).**
- **범용(General Purpose)**: 기본값이고 작업당 지연이 가장 낮다. 단일 영역 파일 시스템은 늘 이 모드다. 문서는 모든 파일 시스템에 범용을 권한다.
- **최대 I/O(Max I/O)**: 이전 세대 모드다. 병렬성이 매우 큰 작업용이지만 지연이 더 크다. 단일 영역이나 탄력적 처리량과는 함께 못 쓴다. 범용 모드에서 IOPS 한도에 가까운지는 CloudWatch `PercentIOLimit`으로 본다.

**처리량 모드(throughput mode).**

| 모드 | 언제 |
|---|---|
| 탄력적(Elastic, 기본·권장) | 부하가 들쭉날쭉하거나 예측하기 어려울 때. 처리량이 알아서 늘고 준다. 읽고 쓴 양만큼 낸다 |
| 프로비저닝(Provisioned) | 필요한 처리량을 알 때. 저장량과 상관없이 정한 처리량을 낸다 |
| 버스트(Bursting) | 저장량에 비례한 처리량이면 될 때. 기준 처리량은 {{fact:ec2.efs.bursting.baseline}}이고, 남는 동안 크레딧을 모아 더 높게 쓴다 |

- 모드는 운영 중에 바꿀 수 있고 중단이 없다. 다만 프로비저닝으로 바꾸거나 양을 늘린 뒤 {{fact:ec2.efs.provisioned.lock}}은 모드를 다시 바꾸거나 양을 줄일 수 없다.
- 버스트 모드에서 처리량이 모자라면 문서는 탄력적이나 프로비저닝으로 바꾸라고 한다.

@topic ec2/instance-store-efs/efs-access-encryption

**액세스 포인트(access point).** 애플리케이션별 진입점이다.
- 액세스 포인트를 거치는 모든 요청에 정해진 POSIX 사용자·그룹을 강제한다.
- 다른 루트 디렉터리를 강제해, 클라이언트가 그 디렉터리 아래만 보게 한다.
- IAM 정책과 묶어 "이 앱은 이 액세스 포인트로만 탑재"를 강제한다. 여러 앱이 한 파일 시스템을 나눠 쓸 때 데이터 범위를 나누는 데 쓴다.
- 네트워크 연결은 탑재 대상이 맡는다. 액세스 포인트를 쓰기 전에 탑재 대상이 하나 이상 있어야 하고, 보안 그룹도 탑재 대상에 걸린다.
- 탑재할 때는 EFS 탑재 도우미(`amazon-efs-utils`)로 `tls`, `accesspoint=` 옵션을 준다.

**IAM 인증.** NFS 클라이언트 접근을 IAM으로 통제할 수 있다. 파일 시스템 정책(리소스 기반 정책)으로 어떤 역할이 탑재하고 쓰기를 할 수 있는지 정한다.

**암호화.**
- **저장 중(at rest)**: 파일 시스템을 만들 때만 정한다. 콘솔은 기본으로 켜고, CLI·API·SDK는 직접 켜야 한다. 만든 뒤에는 바꿀 수 없다. 암호화되지 않은 파일 시스템을 암호화하려면 새 암호화 파일 시스템으로 복제한다. 키는 AWS 소유 키(기본) 또는 고객 관리형 KMS 키다. IAM 조건 `elasticfilesystem:Encrypted`로 암호화하지 않은 생성을 막을 수 있다.
- **전송 중(in transit)**: 탑재할 때 `tls` 옵션으로 켠다. 탑재 도우미가 TLS 연결을 만든다. 탑재마다 켜는 설정이므로 파일 시스템 정책으로 TLS가 아닌 연결을 거부하게 할 수 있다.
- 규제상 데이터와 메타데이터 암호화가 필요하면, 저장 중 암호화로 만들고 전송 중 암호화로 탑재하라고 문서가 권한다.

@topic ec2/instance-store-efs/comparison

세 가지를 한눈에 비교한다. EBS 자세한 내용은 {{ch:ec2/ebs}}에 있다.

| 항목 | EBS 볼륨 | 인스턴스 스토어 | EFS |
|---|---|---|---|
| 종류 | 블록 | 블록 | 파일(NFS) |
| 위치 | 가용 영역 하나 | 그 호스트 | 리전(여러 영역) 또는 단일 영역 |
| 수명 | 인스턴스와 따로 남는다 | 인스턴스가 살아 있는 동안 | 지울 때까지 |
| 여러 인스턴스 동시 사용 | 보통 한 대. io1·io2 다중 연결만 예외 | 안 됨 | 여러 영역의 많은 인스턴스 |
| 크기 | 정해서 만든다 | 유형이 정한다 | 자동으로 늘고 준다 |
| 맞는 곳 | 부트 볼륨, 데이터베이스, 한 대가 쓰는 데이터 | 캐시, 버퍼, 스크래치 | 공유 콘텐츠, 홈 디렉터리, 여러 서버의 공용 데이터 |

고르는 법을 줄이면 이렇다.
- 한 인스턴스가 오래 쓸 디스크 → EBS.
- 잃어도 되는 빠른 임시 공간 → 인스턴스 스토어.
- 여러 인스턴스, 여러 가용 영역이 같은 파일을 봐야 함 → EFS. Auto Scaling 그룹의 웹 서버들이 업로드 파일을 함께 쓰는 경우가 대표적이다({{ch:ec2/auto-scaling}}).
- 파일 시스템이 아니라 객체로 저장해도 되고 어디서나 HTTP로 접근 → Amazon S3. EBS 스냅샷과 S3 기반 AMI도 S3에 저장된다.

**Amazon FSx.** 널리 쓰이는 파일 시스템을 관리형으로 주는 서비스 묶음이다. **FSx for Windows File Server**(Windows SMB 공유, Windows 인스턴스용), **FSx for Lustre**(고성능 컴퓨팅·기계 학습처럼 처리량이 아주 큰 작업), **FSx for NetApp ONTAP**, **FSx for OpenZFS** 가 있다. EFS가 Linux NFS 공유를 단순하게 주는 것이라면, FSx는 특정 파일 시스템의 기능(SMB와 Active Directory, Lustre 병렬 처리, ONTAP 데이터 관리)이 필요할 때 고른다. 새 인스턴스 시작 마법사는 ONTAP와 OpenZFS 파일 시스템을 시작할 때 탑재해 준다. Windows File Server와 Lustre는 시작 뒤에 직접 탑재한다.
