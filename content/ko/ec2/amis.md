@topic ec2/amis/components

**AMI(Amazon Machine Image)** 는 인스턴스를 띄우고 부팅하는 데 필요한 소프트웨어를 담은 이미지다. 인스턴스를 띄울 때는 반드시 AMI를 하나 고른다. 같은 구성의 인스턴스를 여러 대 만들 때는 같은 AMI를 쓰고, 구성이 다르면 다른 AMI를 쓴다.

AMI에 들어 있는 것과 AMI가 정하는 것:

| 항목 | 내용 |
|---|---|
| 소프트웨어 | OS, 애플리케이션 서버, 애플리케이션 |
| 블록 디바이스 매핑(block device mapping) | 인스턴스에 붙일 볼륨 목록. EBS 기반이면 볼륨을 만들 스냅샷을 가리킨다 |
| 시작 권한(launch permissions) | 누가 이 AMI로 인스턴스를 띄울 수 있는가. 퍼블릭, 명시적(특정 계정·조직·OU), 암묵적(소유자) |

AMI는 **리전, OS, 프로세서 아키텍처, 루트 볼륨 유형, 가상화 유형** 에 묶인다. 고른 인스턴스 유형과 맞아야 한다. 예를 들어 x86용 AMI로 Graviton(Arm) 인스턴스를 띄울 수 없다({{ch:ec2/instance-types}}). 가상화 유형은 HVM과 PV가 있는데, 현재 세대 유형은 HVM만 지원한다.

**루트 볼륨 유형: EBS 기반 대 인스턴스 스토어 기반.** AMI는 루트 볼륨을 어디에 두느냐로 나뉜다.

| 구분 | EBS 기반 AMI | Amazon S3 기반 AMI(인스턴스 스토어 루트) |
|---|---|---|
| 루트 볼륨 | EBS 스냅샷에서 만든 EBS 볼륨 | S3에 있는 템플릿에서 만든 인스턴스 스토어 볼륨 |
| 부팅 시간 | 보통 {{fact:ec2.ami.boot.ebs}} | 보통 {{fact:ec2.ami.boot.s3}} |
| 중지(stop) | 된다. 중지해도 루트 볼륨이 EBS에 남는다 | 안 된다. 실행 중 아니면 종료뿐이다 |
| 속성 변경 | 중지한 동안 인스턴스 유형, 사용자 데이터 등을 바꾼다 | 인스턴스 수명 동안 고정 |
| AMI 만들기 | 명령 하나 | AMI 도구를 설치해 번들링 |
| OS | Linux, Windows | Linux만 |

- EBS 기반에서 루트 볼륨은 기본적으로 종료할 때 함께 지워진다(`DeleteOnTermination=true`). 다른 EBS 볼륨의 동작은 {{ch:ec2/instance-lifecycle}}에서 다룬다.
- S3 기반 AMI는 수명이 끝난 방식이다. 문서는 새로 쓰지 말고 EBS 기반을 쓰라고 하며, 일부 이전 세대 유형에서만 돌아간다. 2026년 11월부터는 그 리전에 S3 기반 AMI를 이미 갖고 있는 계정만 새로 만들거나 복사해 올 수 있다(2025년 이후 변경, 시험 범위 여부 불명).

**AMI 만들기.** 기존 AMI로 인스턴스를 띄우고, 소프트웨어 설치와 OS 설정을 한 뒤, 그 인스턴스에서 AMI를 만든다. EBS 기반이면 붙은 볼륨마다 스냅샷이 생기고 AMI가 그 스냅샷을 가리킨다. 기본값은 AMI를 만들 때 인스턴스를 **재부팅** 해 디스크가 쉬는 상태에서 스냅샷을 뜨는 것이다. 재부팅 없이(`--no-reboot`) 만들 수도 있지만, 그러면 파일 시스템 무결성을 보장하지 않는다.

**비용.** AMI 자체가 아니라 뒤에 있는 저장소에 돈이 나간다. EBS 기반은 스냅샷 저장 요금, S3 기반은 S3 저장 요금이다.

@topic ec2/amis/copy-share

**AMI는 리전 리소스다.** 인스턴스는 AMI가 있는 리전에서만 띄울 수 있다. 같은 구성을 다른 리전에서 쓰려면 **AMI 복사(CopyImage)** 로 대상 리전에 옮긴다.

- 복사본은 **새 AMI ID** 를 받는 별개의 AMI다. 원본을 바꾸거나 등록 취소해도 복사본은 영향을 받지 않고, 반대도 같다. 원본을 고친 뒤 대상 리전에도 반영하려면 다시 복사한다.
- EBS 기반 AMI는 뒤의 스냅샷도 함께 복사된다. 새 리전으로의 첫 복사와, 암호화 상태나 KMS 키를 바꾸는 복사는 **전체 복사** 다. 그 뒤의 복사는 증분이다.
- 복사는 **대상 리전에서 시작** 한다. CLI라면 `--source-region`에 원본 리전을, `--region`에 대상 리전을 준다.
- 복사 전에 원본 AMI 안의 설정(DB 연결 문자열 등)을 대상 리전에 맞게 고친다. 그대로 두면 새 리전의 인스턴스가 원래 리전의 리소스를 불러 성능과 비용이 나빠진다.
- 원본 AMI의 태그는 계정 간 복사에서 따라오지 않는다.
- 완료 시간을 정하는 시간 기반 복사도 있다. 추가 요금이 붙는다(2025년 이후 추가, 시험 범위 여부 불명).

리전 간 복사가 쓰이는 곳: 여러 리전에 같은 구성 배포, 사용자 가까이에 두기, 리전 장애에 대비한 다중 리전 설계.

**공유.** AMI 소유자는 시작 권한으로 다른 사람이 AMI를 쓰게 한다.

| 공유 방식 | 내용 |
|---|---|
| 특정 계정·조직·OU | 지정한 대상만 띄울 수 있다. 조직·OU로 공유하면 그 안의 계정 수는 할당량({{fact:ec2.ami.quota.share}})에 세지 않는다 |
| 퍼블릭 | 모든 AWS 계정이 띄울 수 있다. 퍼블릭 AMI는 {{fact:ec2.ami.quota.public}}가 기본 할당량이다 |

- 공유도 리전 단위다. 다른 리전에서 쓰게 하려면 먼저 그 리전으로 복사한 뒤 공유한다.
- 공유받은 쪽은 인스턴스를 띄울 수만 있다. AMI를 지우거나 고치거나 다시 공유할 수 없다. 다만 띄운 인스턴스에서 자기 AMI를 새로 만들 수는 있다.
- 공유받은 AMI를 자기 계정으로 복사하면(계정 간 복사) 복사본의 소유자는 자신이 되고, 대상 리전의 저장 요금도 자신이 낸다.
- 스냅샷은 따로 공유하지 않아도 된다. 다만 암호화된 스냅샷이면 KMS 키 사용 권한을 상대에게 줘야 한다(다음 절).
- **퍼블릭으로 만들 수 없는 AMI**: 암호화된 볼륨이나 그 스냅샷을 담은 AMI, 제품 코드가 있는 AMI. 이런 AMI는 특정 계정에만 공유한다.
- **AMI 퍼블릭 액세스 차단(block public access for AMIs)**: 켜면 AMI를 퍼블릭으로 만드는 시도가 막힌다. 이미 퍼블릭인 AMI는 그대로 남는다. 계정 설정이며 리전마다 켠다. 새 계정과 퍼블릭 AMI가 없던 기존 계정은 기본으로 켜져 있다.
- 다른 사람이 공유한 AMI는 남의 코드다. AWS가 무결성을 보증하지 않으므로 출처를 확인하고 검사한 뒤 쓴다.

@topic ec2/amis/encryption

EBS 기반 AMI의 스냅샷은 EBS 암호화를 그대로 쓴다. AWS 관리형 기본 KMS 키나 지정한 고객 관리형 키로 암호화하며, 어느 경우든 그 키를 쓸 권한이 있어야 한다.

**인스턴스를 띄울 때(RunInstances).** 암호화 파라미터를 주지 않으면 스냅샷의 암호화 상태를 그대로 따른다. 계정에 **EBS 기본 암호화(encryption by default)** 가 켜져 있으면 새 볼륨은 모두 암호화된다.

| 원본 스냅샷 | 파라미터 없음 | `Encrypted`만 | `Encrypted`+`KmsKeyId` |
|---|---|---|---|
| 암호화 안 됨 | 암호화 안 됨(기본 암호화가 켜져 있으면 암호화) | 계정 기본 키로 암호화 | 지정한 키로 암호화 |
| 암호화됨, 내 것 | 같은 키 | 같은 키 | 지정한 키로 다시 암호화 |
| 암호화됨, 공유받은 것 | 내 계정 기본 키 | 내 계정 기본 키 | 지정한 키 |

`KmsKeyId`만 주고 `Encrypted`를 빼면 오류다.

**복사할 때(CopyImage).** 기본은 원래 암호화 상태와 키를 유지한다.

- 암호화 안 된 AMI를 복사하면서 암호화할 수 있다. 다른 키로 다시 암호화할 수도 있다.
- **암호화된 AMI를 복사해 암호화를 풀 수는 없다.**
- 복사로 암호화를 바꾸는 것은 EBS 기반 AMI만 된다. S3 기반 AMI는 스냅샷이 없어 안 된다.

**암호화된 AMI 공유.** 고객 관리형 키로 암호화한 AMI만 공유된다. AWS 관리형 기본 키로 암호화한 AMI는 공유할 수 없다. 공유할 때는 상대 계정이 그 KMS 키를 쓸 수 있게 키 정책을 열어 준다. 공유받은 암호화 AMI로 인스턴스를 띄우면, 파라미터를 주지 않아도 볼륨은 받는 계정의 기본 KMS 키로 암호화된다(위 표).

@topic ec2/amis/lifecycle

AMI의 수명 주기는 **만들기 → 복사 → 사용 중단 → 비활성화 → 등록 취소** 다.

| 단계 | 하는 일 | 기존 인스턴스 |
|---|---|---|
| 사용 중단(deprecate) | 오래됐다는 표시. 지금 또는 미래 날짜를 정한다 | 영향 없음 |
| 비활성화(disable) | 새 인스턴스를 띄우지 못하게 잠시 막는다. 다시 켤 수 있다 | 영향 없음 |
| 등록 취소(deregister) | AMI를 지운다. 새 인스턴스를 띄울 수 없다 | 영향 없음 |

**사용 중단.**
- 사용 중단된 AMI는 다른 사용자의 목록 조회(DescribeImages)와 콘솔 카탈로그에서 숨겨진다. 소유자에게는 보인다.
- 숨겨질 뿐 지워지지 않는다. ID를 알면 API·CLI로 계속 띄울 수 있고, 시작 템플릿과 Auto Scaling 그룹도 계속 참조한다.
- 스냅샷 요금은 계속 나간다. 요금을 멈추려면 등록 취소한다.
- 날짜 상한은 {{fact:ec2.ami.deprecate.max}}다. 퍼블릭 AMI는 기본적으로 생성일로부터 {{fact:ec2.ami.public.deprecate}} 뒤에 사용 중단되고, 이보다 늦출 수 없다. 늦추려면 특정 계정 공유로 바꾼다.

**등록 취소.**
- 등록 취소해도 기본으로 **스냅샷은 남고 요금도 계속 나간다.** 등록 취소할 때 연결된 스냅샷을 함께 지우도록 지정하거나, 나중에 직접 지운다. 다른 AMI도 쓰는 스냅샷은 지정해도 지워지지 않는다.
- 그 AMI로 띄운 인스턴스는 계속 돈다. 필요 없으면 따로 중지하거나 종료한다.
- **등록 취소 방지(deregistration protection)**: 켜면 IAM 권한과 상관없이 누구도 등록 취소할 수 없다. 켤 때 대기 기간을 고르면, 방지를 끈 뒤에도 {{fact:ec2.ami.dereg.cooldown}} 동안 보호가 유지된다. 기본은 꺼져 있다.

**휴지통(Recycle Bin).** 실수로 지운 EBS 기반 AMI를 되살린다. EBS 스냅샷과 EBS 볼륨도 같은 기능을 쓴다.
- **보존 규칙(retention rule)** 을 만든다. 태그 수준 규칙은 지정한 태그가 붙은 리소스만, 리전 수준 규칙은 그 리전의 해당 유형 전체(제외 태그 지정 가능)를 보호한다.
- 규칙에 맞는 AMI를 등록 취소하면 바로 지워지지 않고 휴지통으로 간다. 보존 기간은 {{fact:ec2.rbin.ami.retention.min}}~{{fact:ec2.rbin.ami.retention.max}}에서 정하고, 그 안에 복원하지 않으면 영구 삭제된다. 규칙에 맞지 않으면 바로 영구 삭제된다.
- 휴지통의 AMI를 보고 복원하려면 IAM 권한(`ec2:ListImagesInRecycleBin`, `ec2:RestoreImageFromRecycleBin`)이 따로 필요하다.

**자동화.**
- **EC2 Image Builder**: 맞춤형 "골든" 이미지의 생성·관리·배포를 자동화한다. 소프트웨어를 미리 설치하고 보안 설정과 최신 패치를 반영한 이미지를 꾸준히 만들 때 쓴다. 문서도 이 방식을 권한다.
- **Amazon Data Lifecycle Manager**: EBS 기반 AMI와 스냅샷의 생성, 보존, 복사, 사용 중단, 등록 취소를 정책으로 자동화한다. 스냅샷 쪽 자세한 내용은 {{ch:ec2/ebs-snapshots}}.
