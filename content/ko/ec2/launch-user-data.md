@topic ec2/launch-user-data/launch-settings

인스턴스를 띄우는 방법은 여럿이다. 콘솔의 인스턴스 시작 마법사, 시작 템플릿, 기존 인스턴스를 바탕으로 한 "이와 유사한 항목 시작", AWS CLI·SDK의 `RunInstances`, CloudFormation. 많은 인스턴스를 여러 유형·구매 옵션으로 띄우면 EC2 Fleet을, 상태 확인과 교체·확장까지 자동으로 하려면 EC2 Auto Scaling을 쓴다({{ch:ec2/auto-scaling}}).

어느 방법이든 정하는 설정은 같다. 시험과 실무에서 자주 걸리는 것만 추린다.

| 설정 | 무엇을 정하나 |
|---|---|
| AMI | OS와 소프트웨어. 리전·아키텍처가 맞아야 한다({{ch:ec2/amis}}) |
| 인스턴스 유형 | vCPU·메모리·네트워크 성능({{ch:ec2/instance-types}}) |
| 키 페어 | SSH·RDP 접속에 쓰는 키. 필요 여부는 접속 방법에 따라 다르다 |
| 네트워크 설정 | VPC, 서브넷(곧 가용 영역), 퍼블릭 IP 자동 할당, 보안 그룹({{ch:vpc/security-groups-nacl}}, {{ch:vpc/internet-access}}) |
| 스토리지 | 루트 볼륨과 추가 볼륨, 크기·유형·암호화, 종료 시 삭제 여부 |
| IAM 인스턴스 프로파일 | 인스턴스의 앱이 AWS API를 부를 때 쓰는 역할({{ch:iam/roles}}, {{ch:ec2/metadata}}) |
| 종료 동작, 종료 방지, 중지 방지 | OS에서 끌 때 중지할지 종료할지, 실수로 끄는 것을 막을지({{ch:ec2/instance-lifecycle}}) |
| 최대 절전 동작 | 최대 절전 모드를 쓸지. 시작할 때만 켤 수 있다 |
| 인스턴스 자동 복구 | 시스템 상태 확인 실패 때 다른 하드웨어로 옮길지 |
| 메타데이터 옵션 | IMDS 사용, IMDSv2 필수 여부, 응답 홉 제한({{ch:ec2/metadata}}) |
| 구매 옵션, 용량 예약, 테넌시, 배치 그룹 | {{ch:ec2/purchasing-options}}, {{ch:ec2/spot}} |
| 사용자 데이터 | 첫 부팅 때 실행할 스크립트나 cloud-init 지시어(아래) |

띄운 직후 인스턴스는 `pending` 상태이고, `running`이 되면 부팅이 시작된다. `running`이 된 뒤에도 접속할 수 있기까지 잠시 걸린다.

@topic ec2/launch-user-data/launch-templates

**시작 템플릿(launch template)** 은 인스턴스 시작 설정을 저장해 둔 것이다. AMI ID, 인스턴스 유형, 네트워크 설정 같은 값을 넣어 두면 띄울 때마다 다시 적지 않아도 된다. EC2 콘솔·CLI·SDK뿐 아니라 EC2 Auto Scaling, EC2 Fleet도 시작 템플릿을 받는다.

**버전.**
- 시작 템플릿은 바꿀 수 없다(immutable). 바꾸려면 **새 버전** 을 만든다. 버전 번호는 만든 순서대로 자동으로 붙는다.
- 새 버전은 기존 버전을 바탕으로 만들어 일부 값만 덮어쓸 수 있다.
- 띄울 때 버전을 지정하지 않으면 **기본 버전(default)** 이 쓰인다. 처음에는 첫 버전이 기본이고, 아무 버전이나 기본으로 바꿀 수 있다. CLI에서는 `$Default`, `$Latest`로 기본 버전과 최신 버전을 가리킨다.
- 쓰지 않는 버전은 지운다. 한도는 {{fact:ec2.lt.max}}, {{fact:ec2.lt.versions.max}}이다.

**주의할 점.**
- 모든 파라미터는 선택이다. 템플릿에 AMI ID가 없으면 띄울 때 따로 줘야 한다.
- 만들 때 값을 다 검사하지 않는다. 잘못된 조합(예: 배치 그룹이 지원하지 않는 유형)은 띄울 때 실패한다.
- 템플릿에는 태그를 달 수 있지만 버전에는 달 수 없다.
- IAM 정책으로 시작 템플릿을 써야만 인스턴스를 띄우게 하거나, 특정 템플릿만 쓰게 할 수 있다. 시작 설정을 표준화하는 방법이다.

**시작 구성(launch configuration)과의 관계.** 시작 구성은 Auto Scaling 그룹이 쓰던 예전 방식이다.

| 구분 | 시작 구성 | 시작 템플릿 |
|---|---|---|
| 버전 | 없다. 바꾸려면 새로 만들어 그룹에 다시 연결 | 있다 |
| 새 인스턴스 유형 | {{fact:ec2.lc.new-types.date}}부터 새 유형을 지원하지 않는다 | 지원한다 |
| 새로 만들기 | {{fact:ec2.lc.console.date}} 이후 만든 계정은 콘솔에서 못 만들고, {{fact:ec2.lc.create.date}} 이후 만든 계정은 어떤 방법으로도 못 만든다 | 된다 |

문서는 시작 구성을 쓰는 Auto Scaling 그룹을 시작 템플릿으로 옮기라고 권한다. 여러 인스턴스 유형과 스팟·온디맨드를 섞는 혼합 인스턴스 그룹도 시작 템플릿으로 만든다.

@topic ec2/launch-user-data/user-data

**사용자 데이터(user data)** 는 띄울 때 인스턴스에 넘기는 설정 스크립트다. 패키지 설치, 설정 파일 작성, 서비스 시작 같은 초기화를 자동으로 한다.

**형식.**
- Linux: 셸 스크립트(첫 줄이 `#!`와 인터프리터 경로, 보통 `#!/bin/bash`) 또는 cloud-init 지시어(첫 줄 `#cloud-config`). 둘을 MIME 다중 파트로 섞을 수도 있다.
- Windows: 시작 에이전트(EC2Launch 등)가 처리한다. `<script>`나 `<powershell>` 태그로 감싼다.
- API로 보낼 때는 base64로 인코딩한다. 콘솔과 AWS CLI(`run-instances --user-data`)는 대신 인코딩해 준다.
- 크기 한도는 base64 인코딩 **전** 원본 기준 {{fact:ec2.userdata.max}}다.

**언제, 어떻게 도나 (Linux).**
- 기본값은 **처음 띄울 때의 부팅 한 번만** 실행이다. 재부팅이나 중지 후 시작 때는 다시 돌지 않는다. 매번 돌게 하려면 cloud-init 설정을 따로 바꾼다. Windows는 `<persist>true</persist>`를 넣으면 재부팅·시작 때마다 돈다.
- **루트 사용자** 로 실행된다. 스크립트에 `sudo`를 쓰지 않는다. 만든 파일은 root 소유가 되므로 다른 사용자가 써야 하면 권한을 바꿔 둔다.
- 대화형이 아니다. 사용자 입력을 기다리는 명령은 쓰지 않는다(예: 확인 질문에 자동으로 답하는 옵션을 붙인다).
- 부팅에 그만큼 시간이 더해진다. 인스턴스가 `running`이어도 스크립트는 아직 도는 중일 수 있다.
- 결과와 오류는 `/var/log/cloud-init-output.log`에서 본다.

**보고 바꾸기.**
- 사용자 데이터는 인스턴스 안에서 IMDS로 읽는다(`/latest/user-data`, {{ch:ec2/metadata}}). 콘솔과 CLI로도 볼 수 있다.
- 바꾸려면 인스턴스를 **중지** 해야 한다. 실행 중에는 볼 수만 있다. 루트가 인스턴스 스토어인 인스턴스는 중지할 수 없으므로 바꿀 수 없다.

**보안.** 사용자 데이터는 인스턴스 안에서만 읽히지만 인증이나 암호화로 보호되지 않는다. 인스턴스에 접근할 수 있는 사람, 그리고 인스턴스에서 도는 소프트웨어가 읽을 수 있다. 그래서 **비밀번호나 오래 쓰는 암호화 키 같은 민감한 값은 사용자 데이터에 넣지 않는다.** 앱이 AWS API를 불러야 하면 액세스 키 대신 IAM 역할(인스턴스 프로파일)을 붙이고, 비밀 값은 AWS Secrets Manager나 Systems Manager Parameter Store에 두고 스크립트에서 역할 권한으로 가져온다.

**골든 AMI와 사용자 데이터 나누기.** 오래 걸리는 설치를 모두 사용자 데이터로 하면 띄울 때마다 기다려야 한다. 거의 바뀌지 않는 소프트웨어는 AMI에 미리 굽고({{ch:ec2/amis}}), 환경마다 다른 값이나 마지막 설정만 사용자 데이터로 넘기면 확장할 때 인스턴스가 빨리 준비된다.
