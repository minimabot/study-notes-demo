@topic ec2/purchasing-options/on-demand

EC2는 같은 인스턴스라도 어떻게 사느냐에 따라 값이 달라진다. 기준이 되는 것은 **온디맨드 인스턴스(On-Demand Instances)** 다.

- 장기 약정도 선결제도 없다. `running` 상태인 시간만 초 단위로 내고, 최소 과금 시간은 {{fact:ec2.ondemand.billing.min}}이다. 초당 단가는 고정이다.
- 띄우기, 중지, 최대 절전, 재부팅, 종료를 모두 사용자가 정한다.
- 문서는 짧고 불규칙하면서 중단되면 안 되는 워크로드에 온디맨드를 권한다.
- 용량을 보장하지 않는다. 띄우려는 순간 용량이 없으면 용량 부족 오류(ICE, insufficient capacity error)를 받는다. 용량이 꼭 있어야 하면 용량 예약을 함께 쓴다(아래).
- 리전마다 실행 중인 온디맨드 인스턴스 할당량이 있다. 할당량은 인스턴스 개수가 아니라 **vCPU 수** 로 세고, 패밀리 묶음(예: A, C, D, H, I, M, R, T, Z를 묶은 Standard)마다 따로 있다. 사용량에 따라 자동으로 오르며, 더 필요하면 Service Quotas로 증가를 요청한다({{ch:ec2/limits}}).

다른 구매 방식은 모두 "온디맨드보다 얼마나 싼가", 또는 "온디맨드에 무엇을 더 보장하나"로 이해하면 된다.

@topic ec2/purchasing-options/savings-plans-ri

**Savings Plans.** 시간당 사용 금액(USD/시간)을 {{fact:ec2.term.1y}} 또는 {{fact:ec2.term.3y}} 동안 쓰겠다고 약정하고 할인을 받는다. 약정한 금액까지는 할인된 요금이 적용되고, 넘는 사용은 온디맨드 요금이다. EC2에 쓰는 플랜은 두 가지다.

| 플랜 | 적용 범위 |
|---|---|
| Compute Savings Plans | 패밀리·크기·리전·OS·테넌시와 상관없이 EC2에 적용된다. AWS Fargate와 AWS Lambda 사용에도 적용된다. 할인은 {{fact:ec2.sp.compute.max-discount}} |
| EC2 Instance Savings Plans | 한 리전의 한 패밀리(예: 버지니아의 m5)에 약정한다. 그 안에서는 크기·OS·테넌시를 바꿔도 된다. 할인은 {{fact:ec2.sp.max-discount}} |

- 유연할수록 할인이 작다. 패밀리나 리전을 옮길 계획이 있거나 Lambda·Fargate도 쓰면 Compute, 패밀리와 리전이 정해져 있으면 EC2 Instance가 맞다.
- 결제는 전체 선결제(All Upfront), 부분 선결제(Partial Upfront), 선결제 없음(No Upfront) 중에서 고른다.
- 산 뒤에는 약정 조건을 바꿀 수 없다. 사용이 늘면 플랜을 더 산다. AWS Cost Explorer가 과거 사용을 보고 약정 금액을 추천한다.
- 스팟 인스턴스에는 적용되지 않는다. 스팟 사용은 약정을 소진하지도 않는다.
- 전용 인스턴스의 리전별 수수료는 Savings Plans로 할인되지 않는다.

**예약 인스턴스(Reserved Instances, RI).** 실제 인스턴스가 아니라, 속성이 맞는 온디맨드 사용에 자동으로 붙는 **결제 할인** 이다.

- 가격을 정하는 속성: 인스턴스 유형(패밀리+크기), 리전, 테넌시, 플랫폼(OS).
- 기간은 {{fact:ec2.term.1y}} 또는 {{fact:ec2.term.3y}}이고, 긴 쪽이 할인이 크다. 결제 옵션은 Savings Plans와 같은 세 가지이며, 선결제를 많이 할수록 대체로 더 싸다. 선결제 없음도 기간 전체를 매달 내야 하는 계약이다.
- 자동 갱신되지 않는다. 만료되면 인스턴스는 그대로 돌고 온디맨드 요금으로 돌아간다.
- 산 뒤 취소할 수 없다. 대신 수정, 교환(전환형), 판매(표준형)를 할 수 있다.

| 구분 | 표준형(Standard) | 전환형(Convertible) |
|---|---|---|
| 할인 | 더 크다 | 더 작다 |
| 교환 | 할 수 없다 | 기간 중 다른 전환형으로 교환한다. 패밀리, 유형, 플랫폼, 범위, 테넌시를 바꿀 수 있다. 새 쪽의 가치가 같거나 커야 한다 |
| RI Marketplace | 팔 수도 살 수도 있다 | 팔 수도 살 수도 없다 |

두 클래스 모두 일부 속성은 수정할 수 있다. 전환형도 리전은 바꿀 수 없다.

| 범위(scope) | 리전 RI | 영역 RI |
|---|---|---|
| 용량 예약 | 하지 않는다 | 지정한 가용 영역에 용량을 예약한다 |
| 할인 적용 | 리전 안의 모든 가용 영역. 같은 패밀리라면 크기가 달라도 적용된다(Linux/Unix, 기본 테넌시만) | 지정한 가용 영역의 지정한 유형·크기에만 |

범위는 가격에 영향을 주지 않는다.

**어느 쪽을 쓰나.** 문서는 예약 인스턴스보다 Savings Plans를 권한다. 예약 인스턴스는 특정 인스턴스 구성에 약정하고, Savings Plans는 사용 금액에 약정해 구성을 자유롭게 바꿀 수 있기 때문이다.

@topic ec2/purchasing-options/dedicated

기본 테넌시(tenancy)는 **공유** 다. 여러 AWS 계정의 인스턴스가 같은 물리 하드웨어에서 돌 수 있다. 규정이나 라이선스 때문에 하드웨어를 나눠 쓰면 안 될 때 전용 옵션을 쓴다.

| 구분 | 전용 호스트(Dedicated Hosts) | 전용 인스턴스(Dedicated Instances) |
|---|---|---|
| 무엇 | 물리 서버 한 대를 통째로 쓴다 | 한 계정 전용 하드웨어에서 도는 인스턴스 |
| 과금 | 호스트 단위 | 인스턴스 단위 |
| 소켓·코어·호스트 ID | 보인다 | 보이지 않는다 |
| 호스트 선호도·배치 지정 | 된다. 같은 서버에 계속 둘 수 있다 | 안 된다. 중지 후 시작하면 다른 호스트일 수 있다 |
| 자체 라이선스(BYOL) | 소켓·코어·VM 단위 라이선스를 폭넓게 쓴다 | 일부만(License Mobility를 쓰는 SQL Server, Windows VDA) |
| 용량 예약 | 쓸 수 없다 | 쓸 수 있다 |

- 둘 사이에 성능·보안·물리적 차이는 없다. 차이는 보이는 정보, 배치 통제, 라이선스, 과금 단위다.
- 전용 인스턴스는 다른 계정과 하드웨어를 나누지 않지만, 같은 계정의 전용이 아닌 인스턴스와는 나눌 수 있다. EBS 볼륨은 단일 테넌트 하드웨어에서 돌지 않는다.
- 전용 인스턴스를 띄우려면 VPC 테넌시를 `dedicated`로 만들거나, 기본 테넌시 VPC에서 인스턴스마다 `dedicated`를 지정한다.
- 전용 호스트는 온디맨드로 쓰거나 Savings Plans를 적용하고, 전용 호스트 예약(Dedicated Host Reservation)으로 더 할인받을 수 있다. RDS는 전용 호스트에서 돌릴 수 없다.

고르는 기준: 소켓·코어 단위로 매기는 서버 라이선스(Windows Server, SQL Server 등)를 그대로 가져오려면 **전용 호스트**, 단일 테넌트 하드웨어 요구만 맞추면 되면 **전용 인스턴스** 다.

@topic ec2/purchasing-options/capacity

**온디맨드 용량 예약(On-Demand Capacity Reservations).** 특정 가용 영역에 정한 유형의 용량을 확보해 둔다. 기간 약정이 없다.

- **바로 쓰는 예약**: 만들자마자 쓸 수 있고, 언제든 수정·취소한다.
- **미래 날짜 예약**: 필요한 날짜와 유지 기간을 약정한다. 약정 기간에는 수량·기간을 줄일 수 없고, 취소하면 수수료가 붙을 수 있다. 이미 돌고 있는 인스턴스가 아니라 새로 늘릴 인스턴스를 위한 것이다.
- 유형, 플랫폼, 가용 영역, 테넌시가 맞는 인스턴스는 기본적으로 자동으로 예약에 들어간다(open). 특정 인스턴스만 들어가게 지정할 수도 있다.
- **할인은 없다.** 예약 용량을 쓰든 안 쓰든 온디맨드 요금이 나간다. 할인은 Savings Plans나 리전 RI를 함께 적용해 받는다. 영역 RI의 할인은 용량 예약에 적용되지 않는다.
- 쓰지 않는 예약도 온디맨드 인스턴스 할당량을 차지한다.
- 전용 호스트에는 쓸 수 없고, 클러스터 배치 그룹에는 만들 수 있다.

쓰는 곳: 중요한 행사 전 확장 대비, 고가용성 규정이나 재해 복구를 위해 다른 가용 영역·리전에 용량 확보.

**ML용 용량 블록(Capacity Blocks for ML).** GPU 같은 가속 인스턴스를 미래의 정해진 기간 동안 예약한다. 시작일은 {{fact:ec2.cb.advance.max}}까지 잡을 수 있고, 블록 하나에 {{fact:ec2.cb.instances.max}}까지 담는다. 인스턴스는 EC2 UltraClusters 안에 가깝게 배치된다.

- 쓰는 곳: ML 모델 학습·미세 조정, 짧은 실험, 앞으로의 일시적 추론 수요.
- 취소할 수 없다. 예약 ID를 직접 지정해야 그 안에서 인스턴스가 뜬다. 지원 유형과 리전이 정해져 있다.
- 블록 안의 인스턴스는 온디맨드 할당량에 들어가지 않는다.

| 구분 | 용량 | 할인·약정 |
|---|---|---|
| 온디맨드 용량 예약 | 가용 영역에 예약 | 할인 없음. 약정 없음(미래 날짜 예약은 약정 기간이 있다) |
| 영역 RI | 가용 영역에 예약 | 할인 있음. RI 기간 약정 |
| 리전 RI, Savings Plans | 예약 없음 | 할인 있음. 기간 약정 |

@topic ec2/purchasing-options/compare

| 옵션 | 맞는 경우 | 주의 |
|---|---|---|
| 온디맨드 | 짧고 불규칙하며 중단되면 안 되는 일 | 가장 비싸다. 용량 보장 없음 |
| Savings Plans | 꾸준한 사용. 패밀리·리전 변경 가능성 | 약정 금액은 바꿀 수 없다 |
| 예약 인스턴스 | 구성이 정해진 꾸준한 사용 | 특정 구성에 묶인다. 용량 예약은 영역 RI만 |
| 스팟 | 시점이 유연하고 중단돼도 되는 일 | EC2가 알림 후 회수한다({{ch:ec2/spot}}) |
| 전용 호스트 | 소켓·코어 단위 BYOL, 배치 통제 | 호스트 단위 과금 |
| 전용 인스턴스 | 단일 테넌트 하드웨어 요구 | 소켓·코어가 안 보인다 |
| 온디맨드 용량 예약 | 특정 가용 영역 용량 보장 | 할인 없음. 안 써도 과금 |
| ML용 용량 블록 | 정해진 기간의 GPU 확보 | 취소 불가 |

조합하는 기본 원칙:

- 늘 깔려 있는 기준 부하는 약정(Savings Plans, 필요하면 RI)으로 덮는다.
- 그 위의 변동은 온디맨드로, 중단돼도 되는 부분은 스팟으로 받는다.
- 용량이 반드시 있어야 하면 온디맨드 용량 예약을 두고, 할인은 Savings Plans로 받는다.
- 라이선스·규정 요구는 테넌시(전용 호스트·전용 인스턴스)로 푼다.
